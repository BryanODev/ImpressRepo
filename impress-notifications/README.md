# Impress My Design Jobs

Standalone Trello Power-Up hosted on GitHub Pages. One board button opens a fullscreen dashboard showing the *signed-in user's* active assigned cards on the *current board*.

## What appears

- Card name and all Trello labels
- Current list (location on the board)
- Due date with overdue / next-seven-days emphasis
- Native Trello badges: comment, attachment, checklist progress, votes, watched
- Actual **unread Trello notification count on the card for the signed-in user**
- Filters (All / Unread / Due Soon), search, refresh, click a card to open

**Limitation:** Trello doesn't expose other Power-Ups' custom badges in the standard cards REST API. This dashboard shows native Trello badges, not third-party custom badges. Only unread notifications actually generated by Trello can be shown; ordinary changes may generate no notification.

## Setup

1. Add this folder to your GitHub Pages repository (e.g. `impress-my-design-jobs`). Deploy.
2. Create a **new** Power-Up in https://trello.com/power-ups/admin named `Impress My Design Jobs`.
3. Set iframe connector URL to `https://USERNAME.github.io/REPOSITORY/impress-my-design-jobs/index.html`.
4. Under Capabilities, enable **Board Buttons**. No Card Back Section or Show Settings is needed.
5. In the Trello Auth section, generate an API key for this Power-Up. Paste **only the public API key** into `config.js` in `appKey`. Do not paste an API token or app secret.
6. Under that API key's **Allowed Origins**, add `https://USERNAME.github.io` (just the origin, not the repository path).
7. Commit changes to GitHub Pages. Enable this Power-Up on a board. Click **My Design Jobs** in that board's header.
8. Click **Connect Trello** once per designer to grant read-only authorization. When authorized, their individual dashboard loads.

No extra backend or database. The REST API requests originate in each authorized user's browser. We don't collect or store their tokens in our own infrastructure; Trello's REST client manages its private per-user token storage. Share the API key in GitHub Pages code, but **never** put your Trello API token or secret there.

## Unread limitations

The dashboard calls `/1/members/me/notifications?read_filter=unread` and matches `data.card.id` to assigned cards on the current board. The unread count is not a live push feed; click **Refresh** to re-check it. Requests are capped at 1,000 unread notifications, and a warning appears if there are more. If the notification endpoint fails, unread counts are displayed as unavailable, not zero.

The dashboard does not mark notifications as read. Open the card in Trello to view its messages.

## Troubleshooting

- `Invalid return_url`: check the API key's Allowed Origins (e.g. `https://USERNAME.github.io`) and ensure the key in `config.js` belongs to this Power-Up.
- Nothing appears: verify Board Buttons capability enabled and Power-Up added to that board; use browser hard refresh.
- Some badging missing: other Power-Ups' custom badges aren't part of Trello's built-in `badges` field.
- Authorization blocked in a browser: Trello's REST client can be affected by browser third-party storage partitioning; see Atlassian REST API Client docs.
- If notifications can't be loaded, cards still appear but unread values are unavailable.
